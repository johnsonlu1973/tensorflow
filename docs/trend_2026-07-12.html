# SoC 產品策略分析報告 **分析週期：2026-07-05 ~ 2026-07-07** --- ## 任務一：結構性機會偵測 --- ### 機會 1：邊緣裝置上的「代理型 AI 執行環境」——為離線多模態 Agent 提供專用推論加速 #### Step 1：事實觀察 - [SemiEngineering，2026.07]「邊緣 AI 無所不在、代理型、多模態且硬體加速」→ 事實：業界已將「代理型」列為邊緣 AI 的核心屬性之一。[來源] - [Android Authority，2026.07]「Google Gemma 4 在您的口袋中：如何完全離線執行最新 AI」→ 事實：Google 推出可完全離線運行的小型模型 Gemma 4。[來源] - [EE Times，2026.07.06]「MIPS 轉向 RISC-V：Physical AI 是邊緣的 Agentic AI」→ 事實：MIPS CEO 明確將「邊緣代理型 AI」定位為 RISC-V 的目標市場。[來源] - [Bloomberg Tech，2026.07.06]「ByteDance、阿里巴巴因北京收緊監管而下架 AI 伴侶功能」→ 事實：中國監管收緊，雲端 AI 互動服務被迫下架。[來源] - [科技新報，2026.07]「Meta 員工自建 AI 用量排行榜秀 30 天就破 60 兆 Token，但資料外流迅速撤下」→ 事實：企業內部 AI 用量爆炸性成長，同時暴露資料外流風險。[來源] - [科技新報，2026.07]「呼應 Palantir 特斯拉不再狂燒 Token、限員工用額」→ 事實：企業開始意識到雲端 LLM 的 Token 成本不可持續。[來源] #### Step 2：條件變化分析 - **改變的條件**：小型多模態模型（Gemma 4、Claude Haiku 級別）在 2026 年首次達到「離線可用性能」門檻——3-8B 參數模型能執行實用的多步驟推理任務。[推斷] - **性質**：技術性（模型壓縮/量化技術）＋ 經濟性（Token 成本 vs 本地推論成本反轉）＋ 監管性（中國 AI 監管、資料主權要求）三重同時發生。[推斷] - **時間點**：兩年前（2024）小型模型仍以「玩具級對話」為主，無法執行 Agent 所需的工具調用與多步推理；2026 年 Gemma 4/Phi 級模型已跨越可用門檻。[推斷] #### Step 3：趨勢導出 - **Q1（條件變化）**：小模型能力跨越了「Agent 最低可用門檻」。 - **Q2（機制）**：一旦小模型能執行工具調用，「Agent 邏輯 = 雲端」的架構鎖定被打破 → OEM/企業可將 Agent 部署到裝置端 → 對邊緣 SoC 的 NPU 規格提出新要求（不只是視覺推論，還要支援 KV cache、長 context、tool-calling 延遲）。 - **Q3（為何此時）**：三個門檻同時跨越——(a) 模型能力達門檻、(b) 雲端 Token 成本失控（Meta 30 天 60 兆 Token、特斯拉限額）、(c) 資料主權監管收緊。任一單獨不足，三者疊加使「離線 Agent」從技術選項變成商業必需。 - **Q4（反事實）**：若小模型仍停留在 2024 水準，即使雲端成本再高、監管再嚴，企業也只能接受雲端方案——因此模型能力的躍升是真正的觸發因素。 **因此，產業趨勢是：** 邊緣 AI 從「感知推論」（視覺分類、語音辨識）演進為「代理執行」（多模態理解＋工具調用＋多步推理），推論工作負載的性質根本改變。 驗證：✅ 宏觀 ✅ 長期（5年+）✅ 不可逆（模型只會變小變強，不會反向） #### Step 4：市場新機會浮現 - **Q1（競爭條件改變）**：原本邊緣 SoC 的 NPU 為 CNN/Transformer 推論而設計（優化吞吐量、TOPS/W）；Agent 工作負載卻是「低 batch、長 context、稀疏 tool-calling」——完全不同的最佳化目標。 - **Q2（機制）**：現有 NPU 在 Agent 場景下 TOPS 利用率極低（[推斷] 可能 <30%），但記憶體頻寬需求極高 → 出現「規格好看但實際 Agent 延遲差」的錯配 → 對「Agent-optimized SoC」產生真實需求。 - **為何現有競爭者未滿足**： - Qualcomm/MediaTek 的 NPU 路線圖鎖定在 2024 年前規劃，優化目標是相機/影像 AI（利益慣性） - NVIDIA 專注雲端與汽車，邊緣 SoC 非主戰場 - Apple 有能力做但選擇垂直整合封閉，不對外供貨 - **Q4（反事實）**：若 Agent 趨勢不存在，現有 NPU 規格就是最優解——因此機會確實由趨勢創造。 **因此，市場新機會是：** 為「離線多模態 Agent」設計的邊緣 SoC——針對 KV cache 頻寬、長 context 記憶體階層、tool-calling 低延遲切換做架構級最佳化。目標場景：企業筆電/工作站、車載資訊娛樂、工業 HMI、高階 IoT gateway。 #### Step 5：目標客群與 JTBD **問題 A：為什麼是「企業級裝置 OEM」（Lenovo、Dell、HP 商用線；工業電腦廠商）？** 排除的客群： - ❌ 消費手機廠商：已被 Qualcomm/MediaTek/Apple 綁定，無空間切換 - ❌ 個人開發者/Maker：市場太小、無法承擔差異化 SoC 的 NRE - ❌ 汽車 Tier 1：認證週期太長（5-7年），窗口對不上 **因此目標客群是企業級商用裝置 OEM**，因為：他們正面對「員工要用 AI 但資料不能出公司」的直接壓力，且採購決策由 IT 部門而非消費者主導。 **問題 B：結構性支付意願來源** - 合規壓力：GDPR、企業資料治理、行業法規（金融、醫療、法律）明確禁止敏感資料上雲 - 成本壓力：Meta 60 兆 Token/月、特斯拉限額——企業級 Token 帳單已達董事會議題 - 差異化壓力：商用筆電市場高度同質化，「AI 就緒且離線」是難得的差異化賣點 **問題 C：有能力的廠商為何未解決** - Qualcomm/MediaTek 選擇「不做」——他們的 Snapdragon X / Dimensity 路線圖優先服務消費手機大量出貨市場，商用工作站是次要客群，且改架構會傷害既有 IP 投資（利益衝突） - Intel/AMD 有 CPU/GPU 但無專用 Agent NPU——他們的 NPU（如 Meteor Lake 的 NPU）仍以視覺為主要 benchmark（架構慣性） **因此，JTBD：** 企業商用裝置 OEM 需要在 2026-2028 產品週期中，交付「能離線執行企業 Agent 工作流（文件摘要、程式碼助手、資料查詢）、延遲 <2s、電池續航不受影響」的裝置，以維持商用市場的競爭力。 #### Step 6：痛點 - **具體阻礙環節**：現有 NPU 執行 7B 級模型時，首 Token 延遲 3-8 秒、後續 Token 5-10 tok/s，且記憶體佔用擠壓其他應用——遠低於「Agent 可用」門檻。[推斷，基於公開 benchmark 常識] - **現有方案為何無法改善**：問題不在 TOPS 不足，而在**記憶體頻寬與階層設計**——LPDDR5X 頻寬（~68GB/s）對 7B 模型的 KV cache 訪問成為瓶頸，這是架構級問題而非製程可解。 - **Q4（反事實）**：若能解決此瓶頸，OEM 就無需另尋方案——因此瓶頸真實存在。 - **痛點深度**：[推斷] 支付意願高——商用筆電 BOM 中 SoC 佔 15-25%，OEM 願意為「AI 差異化」多付 $30-80/顆。 **因此，核心痛點是：** 在裝置端執行 Agent 級工作負載時，記憶體頻寬瓶頸導致延遲與功耗都無法達到「使用者無感」的商業門檻。 #### Step 7：客戶價值 **解決方案：** 針對 Agent 工作負載最佳化的邊緣 SoC——大容量 on-die SRAM/L3 for KV cache、專用 attention accelerator、高頻寬記憶體介面（LPDDR5X 8533+ 或 LPDDR6）、支援稀疏計算與動態 batch。 - **機制**：透過將 KV cache 保留在 on-die 大容量 SRAM，消除主記憶體來回搬移 → 首 Token 延遲降至 <1s，功耗降至可接受範圍。 - **效益**：OEM 能宣稱「離線 Agent 就緒」，商用市場售價可提高 $200-500/台，且客戶採購理由清晰（合規＋成本）。 - **成本**：SoC 單價可能較同級高 $30-80，OEM 需驗證整合（工程投入 6-12 個月）。 - **效益 > 成本 機制**：若整機售價提升 $200 而 BOM 增加 $50，毛利改善 $150/台 × 商用筆電年出貨數十萬台 → 效益顯著超過成本。 - **競爭壁壘**：時間窗口約 18-24 個月——Qualcomm/MediaTek 修正架構需要 2 個 SoC 世代（[推斷]），此期間為第一批專注解決此問題的廠商窗口。 - **Q4**：若無 Agent 痛點，此 SoC 相對現有方案並無優勢——因此價值確實來自痛點。 #### Step 8：商業價值 **商業模式：** SoC IP 授權 + 參考設計 + 與少數 OEM 深度合作（不追求量產通吃）。 - **擷取機制**：IP 授權費 + 每顆權利金 + 軟體堆疊訂閱（模型優化工具、Agent runtime）。 - **定價權來源**：軟體堆疊鎖定——一旦 OEM 針對特定 SoC 優化其 Agent runtime（模型量化、算子融合），轉換成本包含 6-12 個月工程重工＋認證重測。 - **護城河動態**： - 加深機制：越多 OEM 使用 → 越多模型針對此架構優化 → 生態鎖定 - 削弱威脅：Qualcomm/MediaTek 2028 年後可能推出對等產品；開源 RISC-V Agent 加速器可能後來居上 - **頂峰時間**：2027-2028 年，之後護城河隨大廠追趕而削弱 - **商業價值上限**：[未驗證，建議搜尋確認] 商用 AI PC 市場規模 2027 預估 5000 萬台，若取得 5-10% 附加，SoC 相關營收上限約 $3-8 億/年。 - **時間窗口**：18-30 個月建立領先，之後需靠軟體生態維持。 --- ### 機會 2：RISC-V 進入「非 CPU 主控」的關鍵基礎設施——儲存與網通控制器 #### Step 1：事實觀察 - ⭐[科技新報，2026.07]「三星 SSD 控制器導入 RISC-V，逐步降低對 ARM 依賴」→ 事實：三星在 SSD 控制器層級開始替換 ARM。[來源] - [EE Times，2026.07.06]「MIPS 轉向 RISC-V，Physical AI 是邊緣的 Agentic AI」→ 事實：MIPS 徹底轉向 RISC-V 並被 GlobalFoundries 收購。[來源] - [EE Times，2026.07.06]「Kioxia 準備好在 AI SSD 中提升 NAND 遊戲」→ 事實：AI 用 SSD 對控制器需求規格提升。[來源] #### Step 2：條件變化分析 - **改變的條件**：ARM IPO 後授權費模式明確化（[推斷] 授權費結構調整），加上美中科技脫鉤使「ARM 授權可能受管制」成為真實地緣風險。 - **性質**：地緣政治性 ＋ 經濟性（授權成本）＋ 技術性（RISC-V 生態成熟度跨越門檻）。 - **時間點**：兩年前 RISC-V 工具鏈與驗證 IP 尚未成熟到能取代 ARM Cortex-M/R；2026 年在特定領域（storage controller、network controller）已達可替換水準。 #### Step 3：趨勢導出 - **Q1**：RISC-V 從「學術/邊緣實驗」跨越到「量產基礎設施可用」門檻。 - **Q2（機制）**：三星這種年出貨數億顆控制器的大戶採用 → 帶動整個工具鏈、驗證 IP、SI/PI 設計知識沉澱 → 中小客戶跟進成本大幅降低 → 正反饋。 - **Q3（為何此時）**：ARM 授權費不確定性 + RISC-V 生態達到臨界規模（[推斷]）+ 中國市場強力推動同時發生。 - **Q4（反事實）**：若無地緣風險，僅靠成本因素不足以驅動三星這種規模的替換——因此地緣是關鍵觸發。 **因此，產業趨勢是：** RISC-V 從「CPU 替代夢想」轉向「特定領域控制器主流」——先在儲存、網通、周邊控制器層級站穩，再逐步向上侵蝕。 #### Step 4：市場新機會浮現 - **競爭條件改變**：控制器 IP 授權市場從「ARM 一家」轉為「多方競爭」。 - **機制**：三星示範效應 → 一線客戶紛紛評估 → RISC-V 核心 IP 提供者（SiFive、Andes、MIPS 新公司）獲得議價空間。 - **現有競爭者為何未充分滿足**：ARM 選擇不降價（利益衝突：全面降價會傷害既有客戶合約），且無法解決地緣風險（結構性）。 **因此，市場新機會是：** 針對「儲存/網通/AI 加速器主控」領域的 RISC-V IP 客製化服務——不是純 IP 授權，而是「IP + DFT + 特定工作負載最佳化」的整合方案。 #### Step 5：目標客群與 JTBD **問題 A：為什麼是「二線儲存/網通控制器廠商」（非三星、非 Marvell）？** 排除： - ❌ 三星/Marvell 等一線：已自研，不需外部方案 - ❌ 純消費 IoT 廠商：出貨量不足以攤提客製 NRE **因此目標客群是二線控制器廠商**（例如慧榮 Silicon Motion、群聯 Phison、以及網通 SoC 二線）——他們有量、有工程能力，但缺自研核心 IP 資源。 **問題 B**：支付意願來自——(a) 一線客戶（如 Kioxia）要求「非 ARM 選項」以降低供應鏈風險；(b) 中國客戶要求本土可控供應鏈。 **問題 C**：ARM「選擇不做」——降價會破壞既有商業模型；SiFive 等純 IP 廠商「做但深度不夠」——他們是 IP 供應商不是 solution 供應商，無法交付「整合驗證方案」。 **JTBD：** 二線控制器廠商需在 2027-2028 產品週期，交付「地緣風險可控、成本較 ARM 方案低 15-25%、性能對等」的下一代控制器，以爭取一線 NAND/網通 OEM 訂單。 #### Step 6：痛點 - **阻礙**：自行整合 RISC-V IP 需要 12-18 個月工程投入 + 驗證，二線廠商缺乏此資源。 - **現有方案為何無法改善**：純 IP 供應商（SiFive）交付的是「核心 IP」，不含 SoC 級整合、DFT、production 級驗證——這需要 solution 供應商角色。 **因此，核心痛點是：** 二線控制器廠商想切換 RISC-V 但缺乏整合能力，現有 IP 供應商停留在核心層。 #### Step 7-8：客戶價值與商業價值（簡化） - **解決方案**：RISC-V 控制器 SoC 平台（含 IP + 週邊 + 韌體框架 + DFT） - **商業模式**：Platform 授權費 + per-unit 權利金 + NRE - **護城河**：韌體框架與參考設計積累的 domain knowledge；轉換成本 = 韌體重寫 - **市場規模**：[未驗證] SSD 控制器年出貨數億顆，若 RISC-V 滲透至 30%，IP+服務市場約 $5-10 億/年 - **時間窗口**：24-36 個月，之後 ARM 可能推出更具競爭力的授權方案反擊 --- ### ✅ 任務一因果鏈完整性審核
